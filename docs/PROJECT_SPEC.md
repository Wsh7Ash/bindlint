# Project Spec — bindlint

- **Name:** bindlint
- **Category:** dev-tool
- **Target user:** DNS administrators and SREs who hand-edit RFC 1035
  master files and want `go vet`-style validation before `rndc reload`.
- **Problem:** Zone-file typos (short SOA, CNAME→IP, bad TTL units, lost
  blank-owner inheritance) break delegation at reload time; generic linters
  do not parse master-file syntax and spinning up a DNS server is heavy.
- **Solution:** An offline Go CLI with an RFC 1035 lexer/parser, 19
  why/fix-explained lint rules, line-accurate error recovery, and
  threshold-based exit codes for CI.
- **Core workflow:** `bindlint lint zone.file [--fail-on warning]` →
  fix findings → exit 0 in CI.
- **Must-have features:**
  - lexer (comments, parens, quotes, leading-space blank owner)
  - parser (directives, TTL units, typed rdata, tolerant recovery)
  - 19 lint rules with why/fix text
  - `--fail-on` threshold → exit codes
  - `parse` JSON dump; `rules` listing
- **Nice-to-have features:** SARIF output, DNSSEC rules, glue checks
  (roadmap).
- **Stack:** Go 1.22+, standard library only.
- **Test strategy:** table-driven lexer/parser tests, per-rule fixtures in
  `testdata/`, end-to-end CLI runs in `RESULTS.md`, `go vet`.
- **Demo/result strategy:** `results/demo-session.txt`,
  `results/parse-dump.txt`, `results/rules.txt` generated by the real CLI.
- **Safety considerations:** offline, read-only, no execution of zone
  content; nothing to harden beyond file access.
- **Definition of done:** `go vet` clean, all tests pass, CLI smoke on
  clean/broken fixtures passes, docs complete, published to GitHub.
